# Release and archiving (S9)

Done by the corresponding author, in this order, after the final manuscript is fixed.

1. **Protocol tag.** Push the tag that marks the frozen protocol (created before any held-out
   run, at commit d091b5b):

       git tag -a protocol-freeze d091b5b -m "Protocol frozen before held-out data"
       git push origin protocol-freeze

2. **Zenodo link.** On zenodo.org, log in with GitHub, open *Settings → GitHub* and switch on
   `DRuanli/dvai`. Zenodo reads `.zenodo.json` for the record's metadata.

3. **Release.** On GitHub, *Releases → Draft a new release*, tag `v2.0.0`, target `main`,
   title "Version accompanying the revised manuscript". Publishing it makes Zenodo archive the
   repository and mint a DOI (shown on the Zenodo record within minutes).

4. **DOI in the paper.** Put the version DOI in the Data and code availability statement and
   in the response to Reviewer 1 (Major 6), and add the DOI badge to README.md.

What the archive contains: code, tests, frozen protocol with its deviations and addendum,
configurations, notebooks, development results, and `results/compact/S5`, from which
`report_endpoints.py` and `summarise_secondary.py` reproduce every held-out number. Raw
replication files are not archived; they are regenerated by `run_s5.py`. ANES texts and
microdata are never included.
